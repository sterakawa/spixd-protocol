# 担当Work向け連携事項

## Motion担当
- 撮影開始ごとに一意な `sessionId` を生成
- JPEGをセッションフォルダに保存
- 最大5枚・無操作30秒・途中終了
- 写真確認画面なし
- 保存完了後に `ready.json` を出力
- `result.json` を読みQRを表示。撮影セッションを混在させない
- モデルとPython環境の配布改善はMotion側の課題

## Windows Client担当
- `ready.json` を検知・スキャン
- `protocolVersion` と画像ファイルの存在・数・相対パスを検証
- 1セッションの写真を1つのSPIXDアルバムとして送信
- 重複処理を防ぐ永続的な処理記録とリトライ
- `result.json` を原子的に書き出す
- 既存の手動アップロード機能は壊さない

## SPIXDサーバー担当
最初に既存のコードとAPIを調査。次を確認:
1. アルバム/受け取りURLの事前発行が可能か
2. 複数JPEGのグルーピング方法
3. サーバー側の冪等キー対応と重複登録時の挙動
4. 画像アップロード完了前にURLを配布できるか
5. アップロード済み画像の管理・公開終了処理
本仕様書はサーバーAPIの新設を先に要求しない。

## 仕様変更ルール
- `protocolVersion` の変更を伴う互換性破壊は議論してから実装
- GitHub Issueで変更理由と影響するアプリを明示する
- 実装者は相手アプリが対応済みと推測しない
