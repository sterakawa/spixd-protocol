# 無人撮影セッション（v0.1 草案）

## 状態
`idle` → `capturing` → `finalizing` → `ready` → `uploading` → `available`

- `idle`: 次の組の開始待ち
- `capturing`: ジェスチャーで撮影。最大5枚。ジェスチャーの再アームは手を戻してから
- `finalizing`: 撮影終了後にJPEGの書き込み完了を確認
- `ready`: `ready.json` 公開済み。アップローダーが引き受け可能
- `uploading`: アップローダーが処理中
- `available`: QR表示に使うURLが利用可能

## 終了条件
- 5枚到達
- 途中終了操作（方式はアプリ側で実装）
- 撮影中の無操作30秒（撮影済みが1枚以上なら送信）
- 0枚で終了した場合はアップロードせず `idle` に戻る

## ファイル受け渡し
推奨構造:
```text
SPIXD-Shared/
  session_<unique-id>/
    001.jpg
    002.jpg
    ready.json
    result.json
```

ファイル監視イベントだけに依存せず、起動時・定期的な再走査も行う。
`ready.json` はJPEGの保存完了後に、一時ファイルを書いて同一ボリューム内でリネームする。
`result.json` も同様に原子的に更新する。
ファイル名と相対パスのみを受け入れ、共有フォルダ外への参照（`..` や絶対パス）を禁止する。

## 障害復旧
- `sessionId` による冪等処理。重複した監視イベントで複数アルバムを作らない。
- 接続失敗・送信失敗時はセッションを保存し、アップローダーで再試行する。
- サーバーが既にアルバムを作成したが応答が失われた場合を考慮する。サーバー側に冪等キー機構があるかを確認するまで「完全な二重作成防止」は未確定。
- QR表示中に次セッションを開始しない。表示終了条件・受け取り完了の判定方式は別途確定する。
- 一時プレビューの禁止は「撮影後の写真確認画面」を対象とする。撮影時のライブビューについては既存アプリ仕様を維持する。

## 先行QRについて
理想は撮影終了を待たず、公開URLを先に確保し、画像アップロードを非同期に行うこと。
ただし**サーバーAPIで先行発行できるか未確認**。初期実装は利用可能なサーバーAPIに合わせる。
