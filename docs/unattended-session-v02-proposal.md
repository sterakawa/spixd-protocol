# 無人撮影セッション：人物検出・グー撮影（2026-10-11更新）

この文書は前回の「ピースサイン・無操作30秒・画面QR表示」案を置き換える最新の運用決定です。実装はまだ未確認です。

## 状態遷移
1. `idle`: 人物が撮影エリアに入るまで待機。
2. `capturing`: 人物検出で新規sessionIdを発行、撮影枚数0。グーサインの立ち上がりで1枚撮影し、JPEG保存完了後にカウント。連続検出による重複撮影を防ぐため、次の撮影には一度グーを解除する。
3. `finalizing`: **保存完了した写真が5枚**になった、または**人物不在が連続30秒**になった時点で終了。0枚ならアップロードしない。
4. `ready`: JPEG書き込み完了後に終了JSON(`ready.json`)を原子的に公開。sessionId、撮影枚数、ファイル一覧、終了理由を含める。
5. `uploading`: C#アップローダーがJSONを検知し、同一アルバムへ一括アップロード。
6. `printed`: アップローダーがSPIXD受取QRを**プリンターに印刷**。印刷結果は必要に応じてMotionへ通知する。

## 決定事項
- 撮影開始は**人物検出**（手の検出だけでは人物検出の代用にならない。認識方式は実装時に決定）
- 撮影トリガーは**グーサイン**（以前のピースサイン案から変更）
- 最大5枚
- タイムアウトは「無操作30秒」ではなく「**人物不在が30秒連続**」
- 写真の確認画面なし、写真選択なし
- QRコードは画面表示を必須とせず、**C#アップローダーから印刷**
- 5枚到達で終了した場合、次の人物を同一セッションに混ぜないため再アーム/人物退出条件を設ける（詳細未決）
- 30秒の人物不在は検出の瞬断でリセットしないよう平滑化する（詳細未決）

## JSON契約への追加候補（スキーマ変更前に両担当と照合）
```json
{
  "protocolVersion": "0.2",
  "sessionId": "session_20261011_142600_001",
  "status": "ready",
  "photoCount": 2,
  "endReason": "person_absent_timeout",
  "files": ["001.jpg", "002.jpg"]
}
```
`endReason` は `max_photos` または `person_absent_timeout`。0枚はreadyを出さない。

既存v0.1 JSON Schemaは変更前の草案。上記は**v0.2変更提案**であり、両アプリ対応前にv0.1スキーマを書き換えない。

## アップローダーへの依頼
- ready.jsonを検知したらsessionIdで重複を防ぎ、画像一覧の全ファイルがあることを検証
- 画像を同一アルバムに送信
- QRコードの印刷はサーバーからのURL/QR発行結果に基づいて行う
- ネットワーク送信成功と**プリンター出力成功**を区別して記録する。印刷失敗時に同一セッションを再アップロードしない
